# 童年游戏制作小助手

> 聊几句，把你的小时候做成一个能走进去的地方。

你小时候住在哪儿、门口有什么、夏天最爱干什么、家人怎么喊你回家 ——
回答这几个问题，就能得到一个能玩、能发给别人的小游戏。

不用写代码，不用会画画。

**为什么是"做给自己人"**：这类东西做出来，第一反应一定是发给某个人看。
所以从第一天起，"做完能发出去"就是这个产品的第一功能，不是附带功能。

## 在线试玩

**https://eurus918.github.io/childhood-game-maker/**

不需要安装任何东西，打开就能做、就能玩。

**它也是一个可以装到桌面的 App（PWA）**：在手机或电脑浏览器里打开上面的链接，
选「添加到主屏幕 / 安装应用」，图标就会出现在桌面，点开是全屏的，
**断网也能玩**。分享链接不变 —— 它同时是一个网页、也是一个 App。

本地跑：

```bash
git clone https://github.com/Eurus918/childhood-game-maker.git
cd childhood-game-maker
npm start
# 打开 http://localhost:5173
```

**零依赖，不用 `npm install`。** 改 `src/` 或 `content/` 里的任何文件，刷新页面就能看到 —— 没有构建步骤，源码就是产物。

> ⚠️ 不能直接双击打开 `index.html`。项目用的是原生 ES Module，
> 浏览器在 `file://` 下会因为 CORS 拒绝加载模块。必须走上面的本地服务器
> （或者任意静态服务器，比如 `python3 -m http.server`）。

## 怎么玩

左边回答 6 个问题，右边那个世界会一样一样长出来：

| 问什么 | 为什么按这个顺序 |
| --- | --- |
| 你小时候住在什么样的地方 | 先定空间 |
| 走出家门，离你最近的是什么 | 还是空间 |
| 夏天你最常干的一件事 | 进入行为（这是主玩法） |
| 再挑一个舍不得删的 | 还是行为 |
| 家人喊你回家吃饭，原话怎么喊的 | 情绪落点 |
| 起个名字 | 交付 |

从外到内、从具体到情绪。你是在回忆里越走越深，不是在填表单。

做完之后：

- **进去玩** —— 方向键走，空格交互（**走到门口按一下就换地方**），`TAB` 换季，`R` 重来；
  手机上点地面走过去，右下角「交互」
- **复制分享链接** —— 整个童年被编进一个 URL，发给谁谁点开就能玩，零后端
- **导出存档** —— 存成 JSON，以后导回来还是那一个夏天

### 五个场景，走门就能换

北方农村是唯一「全场景」的地域：院子和屋里、果园、村边小溪、田埂上，各是一张画。

```
院子 ──┬── 屋里（土炕连着灶台）
       ├── 果园（梨、栗子、山楂、桃、苹果）
       └── 田埂 ── 小溪
```

走到门口按空格就过去。院门口站着姥姥 —— 走到她跟前按一下，她会喊你回家吃饭，
喊的是你填的那句原话。

### 一定要待到天黑

游戏里有昼夜。白天摸鱼、粘知了；**太阳下山之后，树根底下才开始冒知了猴**。

这是刻意的设计：把"等待"变成玩法。有些东西，你得等到天黑。

### 四季：比昼夜更大的一层等待

每季 90 秒，一年 6 分钟，自动往前走（不想等就按 `TAB` 手动换季）。
**季节不对的事做不了** —— 但系统会告诉你该什么时候来：

| 季节 | 能干什么 |
| --- | --- |
| 春天 | 田埂上抓蚂蚱、挖蚯蚓、浇菜园 |
| 夏天 | 溪里摸鱼钓鱼、树上粘知了、天黑摸知了猴 |
| 秋天 | 果园摘山楂梨苹果桃栗子 |
| 冬天 | 灶膛里烤鹅蛋、坐炕上不动 |

「现在夏天，烤鹅蛋得等冬天」—— 这句提示本身也是内容。
走完一整年会结算：摸了多少鱼、摘了多少果子，然后是那句喊你回家的话。

## 三条设计原则

### 1. 壁垒不是生成技术，是素材库

市面同类产品做不好，表面原因是"生成慢、质量差"，真实原因是
**AI 做出来的农村是美式农场** —— 谷仓、拖拉机、玉米地，不是土墙、麦垛、
杨树上的知了。

所以这个项目的核心资产是 `content/`：中国本土的童年记忆素材。
代码谁都能抄，这个抄不走。

### 2. 底层 100% 标准化，表层 100% 个性化

地图坐标、碰撞、玩法机制全部写死在代码里，**模型碰不到**。
模型（和用户）能改的只有：配色、物件、文案、剧情、一句话。

代价是全世界长一个样；收益是生成的东西永远跑得起来、永远走得到。
我们选后者。

### 3. 不要追求耐玩

做出来本质是"贴图收集游戏"，玩十分钟就腻。这没关系。

**它的价值在唤起记忆的那一分钟，不在游戏性。**
所以北极星指标不是 DAU，是"完成率 × 发出去之后真的被玩过的人数"。

## 产品链路

```
采访 Interview ──► 编译 Builder ──► 引擎 Engine ──► 分享 Share
（问出素材）      （素材 → world 配置）  （走进去玩）     （编进一个 URL）
```

| 目录 | 职责 |
| --- | --- |
| `src/interview/` | 提问流、关键词匹配、可选 LLM 适配器 |
| `src/world/` | 答案 → 世界配置；多场景布局；存档与分享编解码 |
| `src/engine/` | 渲染、碰撞、昼夜**与四季**、多场景切换、玩法机制、输入、音效 |
| `src/ui/` | 对话面板与清单 |
| `content/` | 素材库（社区共建） |
| `assets/scenes/` | 五个场景的水彩底图 |
| `sw.js` / `manifest.webmanifest` | PWA：装到桌面、离线可玩 |

引擎里没有"知了"这两个字 —— 它只认识 `world` 里的数字和颜色。
换一份素材，同一个引擎跑出来就是另一种童年。

详见 [`docs/architecture.md`](docs/architecture.md)。

## 三条关于 AI 的边界

**① 默认不用大模型。** 采访匹配是本地关键词匹配，候选只有几十个，
够准、零延迟、零成本、结果可预期。说"村口有棵老槐树"必然落到北方农村，
不会像模型那样偶尔给你一个美式农场。

**② 模型只被允许改写"话怎么说"，不允许生成玩法。**
配了后端代理后，LLM 只做一件事：把素材文案改得更像在跟这个人说话。
坐标、规则、玩法必须来自 `content/` 与引擎 —— 从职责边界上堵死失控。

**③ API Key 永远不进前端。**
`llm.js` 只接受一个你自己搭的后端代理地址。浏览器里的任何字符串都会被看到。
默认不配置时，整个产品完全离线可跑。

## 参与贡献

**最欢迎的不是代码，是你自己的童年。**

往 `content/` 里加一份你家乡的素材，五分钟，不用懂代码。
见 [`content/README.md`](content/README.md) 和 [`CONTRIBUTING.md`](CONTRIBUTING.md)。

提交前跑一遍测试：

```bash
npm test
```

里面有一类特别的测试：**BFS 可达性校验**（`test/reach.test.js`）。
它会对**每个场景**跑一遍 BFS，检查每个玩法点、每扇门都走得到，
还会检查门没有压在玩法点上（否则站在玩法点按空格会被传送走）。

挪一棵树可能把某个玩法点堵死 —— 这种 bug 画面上完全看不出来，只能靠测。

改了 PWA 缓存策略，把 `sw.js` 里的 `CACHE_VER` 加一，老缓存会自动清掉。
