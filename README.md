# 🎮 童年游戏生成器 childhood-game-maker

> 对话式生成「你自己的童年」小游戏 —— 聊几句，把小时候住过的地方，做成一个能走进去的地方。

---

## 它解决什么

「童年」这个题材，攻略和模板都写不出来——每个人的童年不一样：村口的池塘、厂区的篮球架、县城街道的小卖部。

现有做法是给你一个**固定的小游戏**，你只能玩别人的回忆。
这里的做法是反过来：先用**一段采访**问出你的童年（住在哪、和谁玩、玩什么），再把你说过的话变成一个**可以走进去的 2D 世界**——地图、场景、小游戏、昼夜，全部按你的回答生成。

**输入是几段对话，输出是一个带分享链接的、可玩的像素小游戏。**

## 30 秒跑起来

零依赖、零构建、完全离线可跑：

```bash
git clone https://github.com/Eurus918/childhood-game-maker.git
cd childhood-game-maker
npm run dev        # 或 npm run serve，打开 index.html 也可以
```

不配任何 Key 就是完整产品。想接入大模型润色文案，见下文「AI 边界」。

## 产品链路（这是本项目的主线）

```
采访 Interview ──► 世界生成 Builder ──► 引擎运行 Engine ──► 分享 Share
（问出素材）      （素材 → 地图/实体）   （走进去玩）        （序列化成链接）
```

### 1. 采访模块 `src/interview/`

多轮对话式采访：地区（北方农村 / 县城街道 / 厂区大院 / 南方水乡）→ 地形（池塘 / 麦田 / 果园 / 河流）→ 活动（粘知了 / 抓鱼 / 挖知了猴 / 摘果子）→ 时代细节问答。

每一步都带「跳过 / 我不确定」的退路——采访是在帮人回忆，不是在做人脸识别，不能卡死在任何一步。

### 2. 世界生成 `src/world/builder.js`

把采访结果映射成可运行世界：地形铺装、实体摆放、活动小游戏挂载、出生点与可达性（`layout.js` 保证每个挂载点都走得过去，`test/reach.test.js` 专门测这个）。

### 3. 游戏引擎 `src/engine/`

自研轻量 2D 引擎：渲染、碰撞、输入、昼夜循环（`daynight.js`）、音效（`audio.js`）、活动玩法（`actions.js`）。纯 Canvas，零第三方运行时依赖。

### 4. 分享 `src/world/serialize.js`

整个世界序列化成一个字符串，塞进 URL 参数——**对方不登录、不存档，点开链接就走进你的童年**。

## 三个关键决策（也是这个项目真正想表达的产品观）

**① 默认不用大模型。**
采访匹配用的是本地关键词匹配（`matcher.js`），不用 LLM——候选只有几十个，关键词够准、零延迟、零成本、可预期。用户说「村口有棵老槐树」，必然落到北方农村，不会像模型那样偶尔给你一个美式农场。

**② 模型只被允许改写「话怎么说」，不允许生成玩法。**
配了后端代理后，LLM 只做一件事：把采访文案改得更像在跟这个人说话（`llm.js`）。坐标、规则、玩法必须来自 `content/` 与引擎——**生成内容失控的坑，从职责边界上直接堵死**。

**③ API Key 永远不进前端。**
前端只接受一个「你自己搭的后端代理地址」，Key 放在代理上。失败或超时返回 null，调用方用原素材兜底——模型永远不能让流程卡住。

---

## 内容体系 `content/`

所有童年素材都是结构化数据，不是写死的文案：每个地区是一组「地形 + 活动 + 时代问答 + 取舍建议」，新增一个地区/活动只需加一个数据文件并在 `index.js` 注册，引擎零改动。

目前内置：4 个地区（北方农村 / 县城街道 / 厂区大院 / 南方水乡）、4 种地形、4 个活动小游戏、90 年代-00 年代时代细节问答。
